Contenido de la aplicación 
La “Red social” será una aplicación dividida en dos proyectos, uno frontend y otro backend. Deberá contar con los siguientes puntos: 
1. Aplicación frontend en Angular. 
2. Servidor en NestJS.

para el backend usa pipes
* ParseIntPipe: convierte y valida un entero.
* ParseFloatPipe: convierte y valida un número decimal.
* ParseBoolPipe: convierte y valida un booleano.
* ParseUUIDPipe: valida un identificador UUID.
* ValidationPipe: valida objetos utilizando las reglas declaradas en sus DTOs.
npm install class-validator class-transformer
Decoradores de validación frecuentes
* @IsString(): el valor debe ser una cadena de texto.
* @IsNotEmpty(): el valor no debe estar vacío.
* @IsEmail(): el valor debe tener formato de correo electrónico.
* @IsNumber(): el valor debe ser numérico.
* @IsInt(): el valor debe ser un número entero.
* @IsBoolean(): el valor debe ser booleano.
* @IsOptional(): omite las demás validaciones si el valor es null o undefined.
* @MinLength(3): el texto debe tener al menos 3 caracteres.
* @MaxLength(50): el texto no debe superar los 50 caracteres.
* whitelist: true: elimina de los objetos validados las propiedades que no tienen decoradores de validación.
usa validation pipes
* forbidNonWhitelisted: true: en lugar de eliminar las propiedades no permitidas, rechaza la solicitud con un error. Se utiliza junto con whitelist.
* transform: true: permite transformar los datos recibidos a los tipos de los parámetros y a las clases DTO cuando corresponda.
* @Min(1) y @Max(100): establecen límites numéricos.genera los schemas de moongose que requieras
